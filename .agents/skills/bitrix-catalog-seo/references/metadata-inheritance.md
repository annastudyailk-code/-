# Наследование метатегов и источники

## Что не смешивать

| Состояние | API-термин для ориентирования | Как использовать |
| --- | --- | --- |
| Собственные сохранённые шаблоны объекта | BaseTemplate.get() | База локального отката; фиксировать наличие собственного поля и режим наследования |
| Шаблоны объекта и родителей | BaseTemplate.findTemplates() | Определить источник шаблона; результат содержит признак INHERITED |
| Вычисленный SEO-текст | ElementValues / SectionValues / IblockValues, getValues() | Сверить вычисленное значение; оно может быть закешировано |
| Текст в публичном HTML | title, meta description, h1 | Конечная проверка реального вывода страницы |

Не формируй новые локальные шаблоны прямым копированием всего результата findTemplates(): это может закрепить наследуемые тексты на уровне дочернего объекта. Не считай getValues() экспортом собственных шаблонов. Вычисление и кеширование значений могут иметь побочные записи; проверка через PHP на боевом сервере требует отдельного рассмотрения, даже если задача называется чтением.

Различай SECTION_META_TITLE и ELEMENT_META_TITLE: первое относится к разделу, второе к элементам. Форма раздела содержит отдельные блоки настроек разделов и элементов. Изменение шаблона раздела может наследоваться его подразделами. Названия полей, флаги и поддерживаемые коды сверяются со штатной формой установленной версии.

BaseTemplate.set() сохраняет шаблоны в базе, delete() удаляет шаблоны объекта, clearValues() очищает вычисленные значения. Ни один из этих методов не относится к безопасному просмотру. Не предполагай, что частичный массив в set() сохранит остальные поля, пока это не проверено по установленному ядру. Ручное обновление таблиц b_iblock_* не заменяет штатный API и работу с наследованием.

Основной H1 задаётся отдельно от свойства title. ShowTitle(false) выводит основной заголовок; ShowTitle() учитывает свойство title. Последующий SetPageProperty('title', ...) или компонент может изменить браузерный Title после настройки инфоблока. Не меняй H1, чтобы замаскировать ошибочный Title.

В Aspro: Максимум SEO-шаблоны посадочных страниц могут менять названия товаров или предложений только на этой посадочной. Отдельный модуль SEO имеет свои поля и условия применения. Сначала выясни, является URL обычным разделом, товаром или такой посадочной, и установлен ли соответствующий модуль. Наличие шаблона Aspro.Max само по себе не подтверждает наличие дополнительных модулей.

## Версии и границы импорта

Материалы upstream на проверенном коммите указывают main 23.0+ как baseline, но фактически проверены авторами на main 26.800.0, iblock 26.0.100 и seo 26.100.0. Это не доказательство совместимости всех примеров с main 25.750.0, установленным в проекте «Солид Металл». Данная адаптация не переносит новые ORM-особенности, миграции или генератор sitemap из 26.x. Описание старых методов InheritedProperty сопоставлено с официальным справочником; перед программным использованием нужен контроль установленной версии.

В пакет входят только этот SKILL.md, настоящая справка и LICENSE. Здесь нет scripts, hooks, package manifests, сетевых клиентов или runtime-зависимостей. Ссылки служат для чтения справки. Не устанавливаются npx-пакеты и не выполняются команды из внешнего репозитория. tools/verify-skills.php и прочие навыки upstream в этот пакет не входят и не проверялись для запуска на сайте.
